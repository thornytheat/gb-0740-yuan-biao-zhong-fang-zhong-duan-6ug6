# 源表重放终端

数仓值班工程师据原始分区和下游依赖复算回填范围，检查已有版本、输入缺失、迟滞依赖和预计行数。夜间算力只够一部分时，终端按依赖闭合原则把全量排程收敛成一份容量受限的回填承诺：今晚实际能承诺哪些分区、哪些受影响分区必须随其一起等待、剩余容量多少。发布的是离线重放清单，页面上的写入与回滚均在样例快照上演练。

## 启动与演练

运行 `docker compose up --build -d`，访问 `http://127.0.0.1:18429/`。

1. 打开「华东夜班回填」。筛到「阻断」，点开分区查看缺失或过期的上游快照。
2. 切换「两分区演练」，点击「生成重放计划」。`orders` 与 `facts` 各增加 2 行，总行数 20 → 24。
3. 转到「回填承诺」。夜间容量默认 1500 行（可用 `REPLAY_CAPACITY` 或表单覆盖）：今晚承诺 6 个分区，`facts@2026-11-19` 等因容量不足推迟，`day1`/`ops` 的下游随其一起等待，剩余容量一并展示。
4. 转到「回滚校验」。演练只覆盖承诺写入的分区，回滚摘要应与演练前摘要一致。相同清单再运行会复用批次。
5. 下载一份重放清单，包括上游版本、目标版本和前后校验摘要。

`POST /api/plans` 接收 `{"sample":"clean"}` 或表单的 `bundle` JSON 文件，可附 `capacity` 行数。排程、回滚和签发读取同一份承诺：同日迟到修订或容量调整只会生成新承诺，不改写已签发内容；重试复用原批次，不会新增第二份。旧承诺与原批证据只增不删，签发页展示证据是否在位、摘要是否一致，一旦误删便无法回查。模块及字段说明见 [深度登记](docs/DEPTH.md) 和 [数据字典](docs/DATA-DICTIONARY.md)。

运行 `docker compose exec -T app pytest -q` 复核。`docker compose down` 停止应用并保留批次历史。
